\subsubsection{Tool Diversity and Command Usage}
\label{sec:tool-diversity}

The actions $a \in \mathcal{A}$ in Equation~\ref{eq:tool-calls} can be implemented in two distinct ways. First, agents may invoke \emph{native tools} provided directly by the agent framework. For example, \claudecode provides \texttt{read\_file} to retrieve file content, \texttt{edit} to modify code, and \texttt{search\_file\_content} to search within files. Similarly, \qwencode offers \texttt{write\_file} to create files, \texttt{list\_directory} to enumerate directory contents, and \texttt{search\_file\_content} to locate code patterns. These native actions return structured data and integrate tightly with the agent's execution environment. Second, agents may execute \emph{shell-invoked commands} through bash interfaces, including standard Unix utilities (\texttt{cat}, \texttt{sed}, \texttt{grep}), version control tools (\texttt{git diff}, \texttt{git show}), build systems (\texttt{mvn test}, \texttt{ant compile}), and domain-specific frameworks (\texttt{defects4j compile}, \texttt{defects4j test}). Shell-invoked commands provide broader flexibility but require agents to construct command-line invocations and parse unstructured text output.

Different coding agents balance native tools and shell commands differently, reflecting distinct architectural philosophies. Some agents rely exclusively on shell interfaces, executing all operations—file reading, editing, searching, building, and testing—through command-line utilities. Others integrate native framework tools to streamline common tasks while delegating specialized operations to shell commands. This design choice shapes both the diversity of tools employed and the complexity of the agent's interaction with the development environment.

Table~\ref{tab:unique_commands_per_agent} presents the number of unique tools invoked by each agent across all repair attempts in \benchmarkdataset. The total unique count represents distinct commands used at least once during evaluation. Native tools and shell-invoked commands are counted separately to characterize each agent's operational paradigm.

\codex relies exclusively on shell-invoked commands (96 unique commands), executing every action through shell interfaces without native tool support. This terminal-centric design reflects a general-purpose interaction model where file operations, code editing, build execution, and version control are all performed via command-line invocations. \qwencode and \claudecode exhibit similar patterns, using primarily shell-invoked commands (81 and 60 unique commands respectively) with minimal native tool integration (10 and 7 native tools). In contrast, \geminicli demonstrates more balanced usage, employing 11 native tools alongside 27 shell-invoked commands, suggesting tighter integration between agent-specific actions and shell-based workflows.

The variation in command diversity further reveals differences in agent behavior. \codex's 96 unique commands indicate broad exploration of available tools and utilities, potentially reflecting diverse repair strategies or frequent experimentation. \qwencode employs 91 unique commands, similarly suggesting extensive tool usage. \claudecode uses 66 unique commands, representing a more focused toolkit. \geminicli's 38 unique commands constitute the most constrained set, potentially indicating either streamlined workflows or limited exploration during repair attempts.

These differences in tool diversity and implementation paradigms have implications for how agents allocate effort across repair activities. Agents relying on shell-invoked commands must construct command-line invocations and interpret unstructured output, while agents leveraging native tools benefit from structured interfaces and reduced parsing overhead. We next examine how these tools are categorized by function to understand the distribution of effort across different phases of the software engineering lifecycle.
