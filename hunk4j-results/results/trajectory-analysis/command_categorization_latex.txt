\subsubsection{Command Categorization}
\label{sec:command-categorization}

Coding agents execute actions through two primary mechanisms: native tool invocations exposed by the agent framework and shell commands executed via bash interfaces. Native tools include file operations (\texttt{read\_file}, \texttt{write\_file}, \texttt{edit}), codebase navigation (\texttt{glob}, \texttt{list\_directory}), and content search (\texttt{search\_file\_content}, \texttt{search\_class}). Shell commands encompass build operations (\texttt{defects4j compile}, \texttt{javac}), test execution (\texttt{defects4j test}, \texttt{mvn test}), version control (\texttt{git diff}, \texttt{git show}), and text processing utilities (\texttt{sed}, \texttt{grep}, \texttt{awk}).

To systematically analyze tool usage patterns, we categorize all agent actions into 16 high-level functional categories based on software engineering lifecycle phases. Each command is classified according to its primary operational purpose rather than its implementation origin. For instance, both the native tool \texttt{read\_file} and the bash command \texttt{cat} are categorized as READ operations, while both \texttt{edit} and \texttt{sed} fall under WRITE operations.

The categorization schema comprises four major operational phases. \textit{Understanding and Analysis} includes READ (viewing file content: \texttt{cat}, \texttt{head}, \texttt{tail}, \texttt{read\_file}), SEARCH\_CONTENT (searching within files: \texttt{grep}, \texttt{search\_file\_content}), SEARCH\_FILES (file system queries: \texttt{ls}, \texttt{find}, \texttt{glob}), and NAVIGATE (directory navigation: \texttt{cd}, \texttt{pwd}). \textit{Implementation} encompasses WRITE (file modification: \texttt{sed}, \texttt{edit}, \texttt{write\_file}) and TRANSFORM (data transformation: \texttt{tr}, \texttt{cut}, \texttt{sort}). \textit{Build and Test} contains BUILD (compilation: \texttt{defects4j compile}, \texttt{javac}, \texttt{mvn compile}) and TEST (test execution: \texttt{defects4j test}, \texttt{mvn test}, \texttt{pytest}). \textit{Version Control} includes VCS (git operations: \texttt{git diff}, \texttt{git show}, \texttt{git checkout}) and PATCH (patch application: \texttt{patch}, \texttt{apply\_patch}, \texttt{diff}).

Supporting categories capture auxiliary operations. FILE\_OPS includes file system mutations (\texttt{cp}, \texttt{mv}, \texttt{rm}, \texttt{mkdir}), UTIL encompasses shell utilities and control flow (\texttt{echo}, \texttt{xargs}, \texttt{wc}, \texttt{if}), SCRIPT represents interpreted language execution (\texttt{python}, \texttt{perl}, \texttt{bash}), WEB covers web operations (\texttt{curl}, \texttt{wget}, \texttt{web\_fetch}), DEFECTS4J\_OTHER contains non-build/test Defects4J commands (\texttt{defects4j export}, \texttt{defects4j checkout}), and ARCHIVE handles compression utilities (\texttt{tar}, \texttt{zip}, \texttt{gzip}). The OTHER category captures parsing artifacts and miscellaneous commands that do not fit established patterns.

This categorization enables systematic comparison of agent behavior across repair attempts. By analyzing category distributions for successful (Pass) versus unsuccessful (Fail) repairs, we identify patterns in how agents allocate effort across different operational phases during multi-hunk bug repair.

Table~\ref{tab:all_agents_tool_category_pass_fail} presents the distribution of command categories across all four agents, stratified by repair outcome. Each cell shows the percentage of commands in that category relative to the agent's total command executions for that outcome class. For instance, if an agent executed 1,000 commands on successful repairs and 200 were categorized as WRITE, the Pass column shows 20.0\%.
